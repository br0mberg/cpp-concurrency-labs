## Описание задания

В папке `task-concurrency-1` лежит файл `livelock.cpp` — демонстрация классической
проблемы **Livelock** в многопоточном программировании.

### Что такое Livelock?

В отличие от **Deadlock**, где потоки спят в ожидании друг друга, при **Livelock**
потоки активно работают — но не продвигаются к результату. Они постоянно «уступают
дорогу», попадая в бесконечный цикл вежливости.

### Легенда

Два сотрудника (потоки) пытаются одновременно редактировать два документа (мьютексы).
Они используют алгоритм «вежливости» (активное избегание Deadlock):

1. Захватить Документ А.
2. Попытаться захватить Документ Б (`try_lock`).
3. Если Документ Б занят — немедленно освободить Документ А, подождать немного и
   попробовать снова, чтобы не держать ресурсы.

**Проблема**: если оба сотрудника начинают одновременно, они входят в резонанс:

- Поток 1 берёт А, видит что Б занят → бросает А.
- Поток 2 берёт Б, видит что А занят → бросает Б.
- Повторяют бесконечно.

Процессор загружен на 100%, но работа стоит.

- Программа должна завершиться за < 10 секунд.

## Часть 2. Исправление через Randomized Backoff

*Стоимость: 5 баллов*

Создайте файл `fix_backoff.cpp`. Сохраните алгоритм с `try_lock`, но добавьте
**случайную задержку** (Randomized Backoff) перед повторной попыткой. Это
рассинхронизирует потоки и разрушит резонанс.

Идея: если `try_lock` не удался, поток ждёт **случайное** количество времени
перед следующей попыткой. Поскольку задержки разные, потоки перестают действовать
синхронно и перестают мешать друг другу.

Проверка:

```bash
cd build
./fix_backoff
# Ожидаемый вывод: Operations: 20000
```

### Требования к решению

- Файл **не должен содержать** `scoped_lock` (иначе это не Backoff-решение).
- Файл **должен использовать** генератор случайных чисел.
- В `CMakeLists.txt` должен быть раскомментирован таргет `fix_backoff`.
- Программа должна завершиться за < 10 секунд.
- Вывод должен содержать `Operations: 20000`.
