# Задание: Асинхронный логгер (AsyncLogger)

---

Задание выполняйте на ветке `task-concurrency-3` в папке `task-concurrency-3`.

После того, как задание будет выполнено, создайте Merge Request в ветку `main`.

---

## Описание задания

В высоконагруженных системах запись логов в файл (I/O операция) напрямую из рабочего потока недопустима, так как это блокирует вычисления. Рабочие потоки должны быстро сбрасывать данные в буфер, а отдельный фоновый поток — записывать их на диск.

Реализуйте класс `AsyncLogger`, который инкапсулирует потокобезопасную очередь сообщений и фоновый поток для их вывода.

**Не используйте** класс `ThreadSafeQueue` с семинара — реализуйте механику синхронизации внутри логгера явно.

**Не модифицируйте** тестовые файлы (`test_basic.cpp`, `test_concurrent.cpp`, `test_shutdown.cpp`).

## Требования к реализации

### Внутреннее устройство класса

Класс `AsyncLogger` должен содержать:

- `std::queue<std::string>` — очередь сообщений
- `std::mutex` — для защиты доступа к очереди
- `std::condition_variable` — для уведомления фонового потока
- `std::thread` — фоновый поток-писатель
- Флаг остановки (например, `bool stop_`)

### Конструктор `AsyncLogger()`

Запускает фоновый поток, который будет обрабатывать очередь.

### Метод `log(const std::string& msg)`

Добавляет сообщение в очередь и уведомляет фоновый поток через `condition_variable`. Должен работать максимально быстро — захватить мьютекс, положить в очередь, отпустить мьютекс, уведомить.

### Фоновый поток

Спит (через `condition_variable::wait`), пока очередь пуста. При появлении сообщений просыпается и выводит их в `std::cout` (имитация записи в файл). Каждое сообщение — отдельная строка.

### Деструктор `~AsyncLogger()` (Graceful Shutdown)

Это **критически важная** часть. Деструктор должен:

1. Установить флаг остановки под мьютексом.
2. Уведомить фоновый поток (`notify_one`), чтобы он проснулся.
3. Дождаться, пока фоновый поток допишет **все оставшиеся** в очереди сообщения.
4. Только после этого вызвать `join()` на фоновом потоке.

Если деструктор не дожидается опустошения очереди — сообщения теряются. Если `join()` не вызывается — `std::terminate()`.

### Дополнительно

- Копирование и присваивание логгера должны быть **запрещены** (`= delete`).
- Не используйте `ThreadSafeQueue` — вся синхронизация внутри класса.

## Часть 1. Базовое логирование

*Стоимость: 3 балла*

Класс `AsyncLogger` компилируется, содержит требуемые примитивы синхронизации, и корректно обрабатывает простую последовательность сообщений из одного потока.

Проверка:

```bash
cd build
./test_basic
# Ожидаемый вывод (stdout): 10 строк "basic-0" .. "basic-9" (порядок может варьироваться)
```

### Требования

- Файлы `async_logger.h` и `async_logger.cpp` существуют.
- Исходники содержат `queue`, `mutex`, `condition_variable`, `thread`.
- Исходники **не** содержат `ThreadSafeQueue`.
- `test_basic` компилируется и выводит ровно 10 сообщений.

## Часть 2. Потокобезопасность

*Стоимость: 3 балла*

Четыре потока одновременно вызывают `log()`. Ни одно сообщение не должно потеряться, и сообщения не должны быть «порваны» (каждая строка — целое сообщение).

Проверка:

```bash
cd build
./test_concurrent
# Ожидаемый вывод (stdout): 100 строк вида "tN-M" (4 потока × 25 сообщений)
```

### Требования

- `test_concurrent` компилируется и выводит ровно 100 уникальных сообщений.
- Все 100 сообщений присутствуют (ни одно не потеряно).

## Часть 3. Graceful Shutdown

*Стоимость: 4 балла*

В очередь быстро кладётся 1000 сообщений, после чего логгер немедленно уничтожается. Деструктор должен дождаться, пока фоновый поток выведет **все** 1000 сообщений, и только потом завершить работу.

Проверка:

```bash
cd build
./test_shutdown
# Ожидаемый вывод (stdout): 1000 строк "shutdown-0" .. "shutdown-999"
```

### Требования

- `test_shutdown` компилируется и выводит ровно 1000 сообщений.
- Ни одно сообщение не теряется при уничтожении логгера.
- Программа завершается без зависания (не более 30 секунд).

## Критерии оценивания

| Часть | Баллы | Проверка |
|-------|-------|----------|
| 1. Базовое логирование — компиляция, примитивы, `test_basic` | 3 | Наличие примитивов + 10 сообщений в stdout |
| 2. Потокобезопасность — `test_concurrent` | 3 | 100 уникальных сообщений в stdout |
| 3. Graceful Shutdown — `test_shutdown` | 4 | 1000 сообщений в stdout, без зависания |
| **Итого** | **10** | |

## Процедура сдачи задания

1. Создайте в репозитории ветку `task-concurrency-3`.
2. Склонируйте репозиторий и переключитесь на ветку `task-concurrency-3`.
3. Скопируйте шаблон в ветку `task-concurrency-3`. В ветке должна быть папка
   `task-concurrency-3`. Внутри неё — содержимое шаблона плюс ваши решения.
4. Запушьте ветку `task-concurrency-3` в удалённый репозиторий.
5. Создайте Merge Request из ветки `task-concurrency-3` в ветку `main`.
6. В комментариях к Merge Request добавьте проверяющего (ревьюера) —
   именно так мы узнаём, что задание готово к проверке. **Не сливайте**
   этот Merge Request!

## post scriptum

Главная ловушка этого задания — деструктор. Если забыть проверить очередь перед выходом из цикла фонового потока, часть сообщений потеряется. Паттерн такой: фоновый поток просыпается, **сначала** обрабатывает всё, что есть в очереди, и **только потом** проверяет флаг остановки. Удачи!
